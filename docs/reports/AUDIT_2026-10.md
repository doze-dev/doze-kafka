# Audit of the hardening work (phases 1–5), October 2026

Seven independent reviews plus baseline checks of branch `audit-hardening` at
`8ea4136`. Every item was reproduced unless marked *(read)*. Status: `[ ]` open,
`[x]` fixed (with a test that fails when the fix is reverted), `[~]` deferred, with
the reason.

## X — cross-cutting

- [x] X1 The kmsg tagged-field hang fix is a `replace` directive, which importers of
  `server` do not inherit; it also breaks `go install …@version` and pins kmsg.
- [x] X2 Upgrade: the legacy `./meta.db` is only found when the data dir is the literal
  string `./data`; any other spelling silently starts empty and shadows it.
- [x] X3 A partition directory with no registry entry is adopted by a new topic of the
  same name (old records resurface). Also reachable by a late write after delete (S10).
- [x] X4 Requests at versions, or for APIs, outside the advertised profile are decoded
  and answered (Produce v0, Fetch v0, InitProducerId v100, DescribeCluster on v1).
- [x] X5 Tests that spawn the binary bind the default console port and join the real
  `~/.doze` zone.

- [x] K3 The one-protocol-per-group guard is check-then-act across two locks.
- [x] K4 OffsetCommit/OffsetFetch do no member or epoch validation for these groups.
- [x] K5 Topic deleted and recreated between heartbeats: the new id is never assigned.
- [x] K6 Request validation and error codes (UNSUPPORTED_ASSIGNOR, INVALID_REQUEST,
  UNKNOWN_MEMBER_ID, epoch below -2).
- [x] K7 `SubscribedTopicRegex` is advertised (v1) and ignored.
- [x] K8 Static membership is not implemented.
- [x] K9 `uniform` is per-topic round robin: unbalanced across topics, not sticky.

### How the U items were checked

Each has a check in `console/testdata/browser-audit.cjs`, which drives a real
browser (Playwright) against a running broker. All of them fail against the
console as it stood at `53abec1` and pass now. Five of those failures (U4, U6,
U12, U14, U23) are the script timing out on markup that did not exist then, so
they show the new behaviour but not, by themselves, the old defect; the audit
reproduced those defects by hand. The script is not run in CI yet: it becomes
Playwright specs in work package 7.4.

The same commit replaced the console's theme (palette and IBM Plex fonts from
the "paper and highlighter" design). `TestThemeContrast` holds every text
colour to 4.5:1 on every surface in both themes.

## After the audit: console additions (asked for on review)

- [x] N1 Moving between topics was jumpy: the "Consumed by" strip was fetched after
  the page and pushed everything below it down a line, and each click redrew the whole
  workspace, list included. The strip is now part of the page and always takes its
  line; a click in the list replaces only the detail pane.
- [x] N2 The composer stays open through a change of partition and closes on a move to
  another topic. This reverses U11, which asked for it to be remembered everywhere: in
  use, an open composer followed you to the next topic and covered its messages.
- [x] N3 One partition's committed offset can be set (a number, or either end) or
  removed; a reset can be limited to one topic.
- [x] N4 `OffsetDelete` removes an offset whose topic no longer exists, where it used
  to answer UNKNOWN_TOPIC_OR_PARTITION and leave it in place.
- [x] N5 Search within a topic's records (keys, values, headers), one partition or
  all, bounded and explicit about how far it read.
- [x] N6 A topic's own `retention.ms`, `retention.bytes` and `segment.bytes` are in
  force (they were stored and reported, and changed nothing), at creation and through
  `AlterConfigs` / `IncrementalAlterConfigs`, which are new. The create-topic form and
  the topic page take them. This is work packages 10.1 and 10.2 of the plan, brought
  forward; `cleanup.policy=compact` is still accepted and not applied.
