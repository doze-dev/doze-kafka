# Audit of the hardening work (phases 1–5), October 2026

Seven independent reviews plus baseline checks of branch `audit-hardening` at
`8ea4136`. Every item was reproduced unless marked *(read)*. Status: `[ ]` open,
`[x]` fixed (with a test that fails when the fix is reverted), `[~]` deferred, with
the reason.

## X — cross-cutting

- [x] X1 The kmsg tagged-field hang fix is a `replace` directive, which importers of
  `server` do not inherit; it also breaks `go install …@version` and pins kmsg.
- [x] X2 Upgrade: the legacy `./meta.db` is only found when the data dir is the literal
  string `./data`; any other spelling silently starts empty and shadows it.
- [x] X3 A partition directory with no registry entry is adopted by a new topic of the
  same name (old records resurface). Also reachable by a late write after delete (S10).
- [x] X4 Requests at versions, or for APIs, outside the advertised profile are decoded
  and answered (Produce v0, Fetch v0, InitProducerId v100, DescribeCluster on v1).
- [x] X5 Tests that spawn the binary bind the default console port and join the real
  `~/.doze` zone.

## S — storage

- [x] S1 A roll racing an in-flight fsync that then fails leaves a sealed segment
  unsynced while the write is acknowledged.
- [x] S2 `Partition.Sync` treats `ErrClosed` as success even when the flush never happened.
- [x] S3 `Bounds` over-reports the end after a torn tail (checks less than recovery).
- [x] S4 Topic names differing only in case share a directory on case-insensitive filesystems.
- [x] S5 Topic cache and bbolt can diverge under concurrent create/delete of one name.
- [x] S6 A group id containing NUL reads and deletes another group's offsets.
- [x] S7 A commit landing after `DeleteTopic` survives into the re-created topic.
- [x] S8 An index write failure after the log write hands out the same offset twice.
- [x] S9 The manager is usable after `Close`; a second `Close` errors.
- [x] S11 Two brokers can share a data dir when `--meta-db` differs.

## K — KIP-848 coordinator

- [ ] K1 A revoked partition is freed when the smaller assignment is sent, not when the
  member acknowledges: double ownership with a client that heartbeats mid-reconcile.
- [ ] K2 No rebalance timeout: a member that never acknowledges blocks its partitions
  forever; unverified ownership claims are accepted.
- [ ] K3 The one-protocol-per-group guard is check-then-act across two locks.
- [ ] K4 OffsetCommit/OffsetFetch do no member or epoch validation for these groups.
- [ ] K5 Topic deleted and recreated between heartbeats: the new id is never assigned.
- [ ] K6 Request validation and error codes (UNSUPPORTED_ASSIGNOR, INVALID_REQUEST,
  UNKNOWN_MEMBER_ID, epoch below -2).
- [ ] K7 `SubscribedTopicRegex` is advertised (v1) and ignored.
- [ ] K8 Static membership is not implemented.
- [ ] K9 `uniform` is per-topic round robin: unbalanced across topics, not sticky.
- [ ] K10 State reporting: order-sensitive Stable check, case-sensitive ListGroups filters,
  empty 848 group listed as classic.
- [ ] K11 Session timers are not stopped at shutdown *(read)*.

## P — protocol and handlers

- [x] P1 Decoding can allocate ~86x the frame size (array counts sized before validation).
- [x] P2 Without SASL nothing bounds a peer: no deadlines, no connection cap, 100 MiB frames.
- [x] P3 A Fetch long-poll outlives its client; MaxWait is uncapped.
- [x] P4 Pre-auth timeout is reset per frame; failed authentication does not close.
- [x] P7 Fetch MaxBytes is not applied to the first partition and starves later ones.
- [x] P8 A fetch with an erroring partition still waits MaxWait; no wake on topic create/delete.
- [ ] P9 Idempotence: overlapping batch dropped as success, retry after eviction appended
  twice, sequence wrap refused.
- [ ] P10 Metadata v0–v3 never auto-creates.
- [ ] P11 ListOffsets v0 returns no offset; timestamp lookups return the earliest *(the
  latter is Phase 10.5)*.
- [ ] P12 Per-topic configs stored and echoed but not validated or applied *(applying is
  Phase 10.1; validation here)*; duplicate names and bad partition counts in CreateTopics.
- [x] P13 SASL: empty password accepted, handshake v0 advertised but not implemented,
  failed re-auth leaves the connection authenticated, SCRAM reveals unknown users.
- [ ] P14 Produce: absurd record counts, client-sent control batches, invalid acks accepted.
- [x] P15 Fetch sessions answered as success.
