# Claims: Traffic stage

The stage's recording queue (R1 to R9, `plan/stages/traffic.md` section 8) and the
claims the console's explainers make about Kafka. Every row is `recorded` or `spec`:
a scenario was run against `apache/kafka:4.3.1` in Docker and its answers are the
committed file named in Evidence, and doze-kafka was made to answer the same (the
replay, `go test ./conformance`, runs without Docker). Where a row says "not replayed"
the scenario defines a `CLIENT_METRICS` resource, which this broker does not have, so it
is evidence for the rules the replayed scenarios and the unit tests hold the broker to.

A broker with nothing configured does not advertise `GetTelemetrySubscriptions` and
`PushTelemetry` at all (row R5), but answers them when sent. The recordings below are of
the raw requests, which is what a client that does speak them (a plugin implementing
`ClientTelemetry` is configured) gets.
